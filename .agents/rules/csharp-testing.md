# C# Testing Rules

Source of truth: spec §4b.5 (`docs/superpowers/specs/2026-10-09-agent-readiness-design.md`).

Each rule names the check that enforces it. "Gap — R1b" means the check doesn't exist yet: follow the rule by hand.

| Rule | Check |
|---|---|
| Red test committed before the code | Commit history (the `/specToProvenPR` red-commit rule); review |
| Every test has exactly one `Lane` trait | Partly: `LaneCap` (`LANE-TEST-002`, below) fails a test with several `Lane` traits or an unknown one in any CTRF report it reads, and a test with none in the report of an unfiltered run (a lane filter never selects it). Gap — R1b for the rest. Planned check: a CI step after the solution build that reads the built `Aw.*.Tests` assemblies (by path, with Mono.Cecil or reflection) and names each test with zero or several `Lane` traits. It can't be an `Aw.Architecture.Tests` rule over a `ProjectReference`: the `*.Tests` projects are leaves nothing may reference (`DEPS-PROJ-003`). A count check alone (unit + integration + heavy = unfiltered) misses a test with no trait offset by one with two |
| Lane budgets (below) | **Per-test cap:** `LaneCap` in `Aw.Kernel.Testing` (`LANE-TEST-001`) checks each test's own time in xUnit's CTRF report against its lane's budget: run the lane with `--report-xunit-ctrf --results-directory <dir>` (no `--report-xunit-ctrf-filename`: with `--solution` every test project would write the same file and only the last report would survive), then `dotnet run --project tests/Aw.LaneCap.Testing -- <dir>` (every `*.ctrf` report in it; the CI .NET job runs it on the unfiltered test run, so it also catches a test with no `Lane` trait; exit 0 pass, 1 a violation, 2 a usage or input error, including no test in any report; each failure prints the rule id, the package, the test, the measured seconds, the limit and the fix). **Per package:** `node scripts/ci/lane-budgets.mjs` (CI's .NET job, after the Release build) times `dotnet test --project <test project> --no-build --configuration Release --filter-trait "Lane=<lane>" --ignore-exit-code 8` per test project, sums the wall clock per `deps.yaml` package (longest `projectPrefix`; a test assembly no package owns, such as `Aw.Architecture.Tests`, is its own row, and so is a project listed in `PROJECT_BUDGETS` of `scripts/ci/lane-budgets.mjs`, with its own limits and out of its package's sum: `Aw.Sindri.Engine.Tests`, owner, 2026-10-18) and fails a package at or over its budget with `LANE-PKG-001` (package, lane, measured seconds, limit, the slowest project and the command to measure it); a timed run that fails is `LANE-PKG-002`. The time is the test run with each test host's start-up, not the compile |
| No mocking libraries | Not in `Directory.Packages.props`; review rejects them |
| A fake and its SQL implementation pass the same contract tests | The contract-test base (per port): for the Kernel ports `ReadRepositoryContract`, `UnitOfWorkContract`, `OutboxContract` and `IdGeneratorContract` in `Aw.Kernel.Testing`, bound to the fakes (`tests/Aw.Kernel.Testing.Tests`), to the `Aw.Kernel.Data` adapters (`tests/Aw.Kernel.Data.Tests/Sqlite*ContractTests.cs`) and, for ids, to the judge's `RandomIdGenerator` (`tests/Aw.Judge.Tests/Ids/`); review checks every new port has one |
| Architecture rules (§4b.1) | ArchUnitNET in `tests/Aw.Architecture.Tests` over every assembly in its `Packages.cs` registry (`ARCH-REG-001` fails when a production project in `AgenticWorkflow.slnx` isn't registered) |
| DI validation per host | The host's `HostTests` (generated by `/new-package`) |

## Red first

- Every slice starts with a failing test that names the behavior: `StartItem_parks_when_budget_is_exhausted`.
- The red commit compiles: it carries the test plus request and response records and a service stub with **no constructor parameters** whose `Handle` throws `NotSupportedException` (an unread constructor parameter is `CS9113` and a `NotImplementedException` is `MA0025`, both errors). `dotnet build` stays at zero warnings and the test fails at run time. The ports arrive in the implement step. `/new-slice` generates exactly that.
- A red placeholder is `Assert.Fail("red: <what to assert>")`, never a `TODO` comment (`MA0026` is an error).

## Organization

- Tests by **feature**, not by layer: `StartItemTests`, not `ItemRepositoryTests` + `ItemServiceTests`.
- Per package: `tests/Aw.<Pkg>.Tests/` (by feature) and `tests/Aw.<Pkg>.Testing/` (fakes, builders, contract bases); project names and root namespaces match their folders, like `tests/Aw.Architecture.Tests/`, which holds every §4b.1 rule.
- `Aw.<Pkg>.Testing` is **test-support** (as `deps.yaml` marks `KernelTesting` with `test: true`): it may reference test-support packages such as `Aw.Kernel.Testing` (the generic contract bases) without a declared edge, only `*.Tests` and `*.Testing` projects may reference it, and it's exempt from fan-out like `*.Tests`. `*.Tests` projects are leaves: nothing references them. Check: `node scripts/check-deps.mjs`.
- Tests reach `internal` types through `InternalsVisibleTo`: `Core`, `Features` and `Infrastructure` declare it for `Aw.<Pkg>.Tests` and `Aw.<Pkg>.Testing`; `Host` declares it for `Aw.<Pkg>.Tests` only. In the small shape `App` declares it for both, and `Aw.<Pkg>.Testing` declares it for `Aw.<Pkg>.Tests` because its builders over `App`'s internal records are internal.
- The test policy applies **by location**: every `*.Tests` and `*.Testing` project lives under `tests/` (including `tests/Aw.Kernel.Testing/`), and #89's `tests/.editorconfig` (`root = false`) covers everything there; outside `tests/` it doesn't apply. It sets: `CA1707` (underscore test names), `RS0016`, `RS0017`, `RS0036`, `RS0037` (no public-API tracking), `CA2007` and `CA1515` (xUnit needs public test classes; xUnit1030 forbids `ConfigureAwait(false)` in tests) are off; `GenerateDocumentationFile` stays `true` (IDE0005 needs it) with `CS1591` off. Test classes are `public sealed`, test names use underscores, and tests `await` without `ConfigureAwait`. `Aw.<Pkg>.Testing` code (fakes, builders, contract bases) gets the same policy because it lives under `tests/` too. A small package's `Aw.<Pkg>.Testing` also has its own `.editorconfig` (written by `/new-package`) turning `MA0182` off, because its internal builders are used only from `Aw.<Pkg>.Tests` through `InternalsVisibleTo`.
- One top-level type per file, named after it (`MA0048`): builders go in `A.cs`, not `Builders.cs`.

## Lanes

Lanes are xUnit traits named `Lane`. Every test carries exactly one. A budget covers the **whole package's run of that lane** (spec §4b.5: "under 10 s per package"), not a single test, and it is also the cap on each single test (`LaneCap`, table above); `node scripts/ci/lane-budgets.mjs` checks the per-package run (table above).

| Lane | What | Budget (whole lane, per package) |
|---|---|---|
| `unit` | `Core` logic and services with in-memory fakes. No I/O | < 10 s |
| `integration` | Repositories on a real temp SQLite file; endpoints on the real host on loopback (`LoopbackBinding` + `Pipeline.Configure`, as the scaffolded tests do) or through `WebApplicationFactory`; the architecture tests (`Aw.Architecture.Tests`: they load every assembly, and four take 22 to 27 s each, over the unit per-test cap; owner, 2026-10-16) | < 60 s; `SindriUi` < 90 s (headless Avalonia rendering; owner, 2026-10-16, `PACKAGE_BUDGETS` in `scripts/ci/lane-budgets.mjs`); `Sindri` < 120 s (real Temporal servers; owner, 2026-10-16: 63.7 s in CI after fail-fast + 8 threads); `Aw.Sindri.Engine.Tests` < 120 s as a row of its own, kept out of the `Sindri` sum (the Temporal-bound suites split out of `Aw.Sindri.Tests` so that package fits its budget on a loaded box; `PROJECT_BUDGETS` in `scripts/ci/lane-budgets.mjs`; owner, 2026-10-18) |
| `heavy` | Real containers, browsers, index builds, multi-megabyte real-clock scale cases | none; nightly, or under a slot of the heavy-job lock (at most two heavy jobs at a time) |

```csharp
[Fact, Trait("Lane", "unit")]
public void StartItem_parks_when_budget_is_exhausted() { … }
```

Run a lane (xUnit v3 on Microsoft.Testing.Platform, which needs `"test": { "runner": "Microsoft.Testing.Platform" }` in `global.json`):

```bash
dotnet test --solution AgenticWorkflow.slnx --filter-trait "Lane=unit" --ignore-exit-code 8
dotnet test --solution AgenticWorkflow.slnx --filter-not-trait "Lane=heavy" --ignore-exit-code 8
```

Exit code 8 means a test project had no test in the filtered lane (an integration-only project in the unit lane, for example). It is fine **only for filtered runs**, hence `--ignore-exit-code 8` there. The unfiltered `dotnet test --solution AgenticWorkflow.slnx` keeps 8 as a failure: a project with no tests at all is a mistake.

The test framework is decided (R7, R1a spike): xUnit v3 on Microsoft.Testing.Platform, lanes as traits.

## Fakes, not mocks

- Each port has **one** in-memory fake in `Aw.<Pkg>.Testing`. No mocking libraries (Moq, NSubstitute, FakeItEasy): they're not in `Directory.Packages.props` and review rejects them.
- A generic contract-test base (`ReadRepositoryContract<TEntity, TId>`, `ItemRepositoryContract`) runs the **same tests against the fake and the SQL implementation**, so the fake can't drift. Every new port gets its contract base in the same PR as its fake.
- The Kernel ports ship theirs in `Aw.Kernel.Testing`: `ReadRepositoryContract<TEntity, TId>`, `UnitOfWorkContract` (fake: `InMemoryUnitOfWorkFactory`, whose `InMemoryUnitOfWork.Enlist` lets a package's fake repositories write only on commit), `OutboxContract` (fake: `InMemoryOutbox`; `InMemoryOutbox.In(work)` is the view whose writes join an `InMemoryUnitOfWork`) and `IdGeneratorContract` (fake: `SequentialIdGenerator`, deterministic by design, so its binding sets `Deterministic`). A binding is a sealed test class deriving from the base, with `[Lane(TestLane.Unit)]` for a fake and `[Lane(TestLane.Integration)]` for SQL (`tests/Aw.Kernel.Data.Tests/Sqlite*ContractTests.cs`).
- `InMemoryUnitOfWork` has two limits a SQL unit doesn't: a fake repository can't read its own enlisted writes before the commit, and a write that throws during `Commit` leaves the writes before it applied. Don't write a test that depends on either; cover that behavior in the SQL integration test.

## Test data

- Builders with sensible defaults: `AnItem().WithSize(S).Build()`.
- Deterministic ids (a fake `IIdGenerator`) and `FakeTimeProvider`; never the wall clock, `Guid.NewGuid` or `Thread.Sleep` in a test (`BannedSymbols.Tests.txt` checks it; `Aw.Kernel.Testing.RealTime` is the named exception for real time, GUID names and sleeps). `CA2000`, `CA2213`, `CA2100` and `CA1508` are off under `tests/` (`tests/.editorconfig`).
- No shared mutable fixtures; each test builds its own state.
- Golden files for CLI output and JSON contracts, recorded from the **C# build** (the golden-file assertions live in `Aw.Kernel.Testing`). Compare after the declared normalization (ids, times), never by loose matching. Update a golden file only in a reviewed change that says why the contract changed.

## Architecture tests

ArchUnitNET (not NetArchTest), in the `integration` lane (owner, 2026-10-16), in `tests/Aw.Architecture.Tests`. Each failure line names the rule id, what it found and the fix.

| Rule id | Rule |
|---|---|
| `ARCH-DIR-001`…`005` | Dependency direction: Core → nothing else in its package; Features → Core, Features; Infrastructure → Core, Infrastructure; another package only through its Core; Core and Features use no tier-0 package but `Aw.Kernel` |
| `ARCH-COMPOSE-001` | A Host uses a `compose` target's Features and Infrastructure (a `deps.yaml` compose edge) only through their public static `Add…()` registration methods; that use is the one `ARCH-DIR-004` carve-out |
| `ARCH-PLACE-001` | Every type of a Core, Features or Infrastructure project sits in that project's layer namespace (small shape: `App`, `App.Features`, `App.Infrastructure`, `App.Commands`): not the bare root, an unknown folder, another layer's namespace or one outside the root. In a Host or App project, anything outside the root counts as Host. IDE0130 (namespace matches folder) catches most of this at build time; this is the backstop |
| `ARCH-SLICE-001` | No slice uses another slice (`Features.<Slice>`, `App.Features.<Slice>`) |
| `ARCH-INFRA-001` | Only the `*ServiceCollectionExtensions` class is public in Infrastructure |
| `ARCH-CYCLE-001` | No namespace cycles in any assembly |
| `ARCH-NAME-001` | No `Common`, `Shared`, `Utils` or `Helpers` namespace or project |
| `ARCH-DI-001` | Service-locator types only in Host (with `Program`; small shape: the `App` root namespace and `App.Commands`) and `*ServiceCollectionExtensions` classes |
| `ARCH-PORT-001`, `002` | No technology type in Core, Features or the small shape's `App.Commands`; only `Composition` uses Infrastructure |
| `ARCH-ID-001`, `002` | `TypedIdGuard`: the VogenDefaults block, and every id and id property (`docs/csharp/typed-ids.md`) |
| `ARCH-REG-001`, `002`, `003` | `Packages.cs` lists every production project in the solution (by project name; analyzers excluded), each one's assembly (its `<AssemblyName>` if set) loads, and a project that is neither tier 0 nor a layer project is declared in `Packages.Unshaped` (the UI and its heads) |
| `ARCH-ASYNC-001` | Every `Task`/`ValueTask` method on a Core interface (a port) takes a `CancellationToken`; `DisposeAsync` is exempt |
| `ARCH-UI-001` | The UI package: no UI type uses a Sindri type; a view model uses no `Avalonia.*` type; a platform head holds no view or view model |
| `ARCH-ENGINE-001` | The Temporal boundary: only `Aw.Sindri.Workflows` (the worker and the engine read adapter) references the `Temporalio` package, and only types in `Aw.Sindri.Infrastructure.Workflows` use a `Temporalio` type; the app, the CLI, the UI and the MCP server hold no Temporal client (API spec P13) |

The layer rules apply to shaped packages (assemblies named `Aw.<Pkg>.Core`, `.Features`, `.Infrastructure`, `.Host`
or `.App`, and not tier 0 in `deps.yaml`, which `RegistryTests` checks against `Rules/TierZero.cs`); tier-0 packages (`Aw.Kernel`, `Aw.Kernel.Data`) get the cycle, naming, service-provider and typed-id rules.
A type outside every package root in a package's `Host` or `App` assembly (the top-level-statement `Program`, generator
output) counts as Host. ArchUnitNET records no dependencies from a top-level-statement body (`<Main>$`), so what
`Program` itself calls is checked by review, not by these rules. A new package registers each production project in `tests/Aw.Architecture.Tests/Packages.cs`
(one line, the project name) and adds a `ProjectReference` to it in `Aw.Architecture.Tests.csproj`; `/new-package` does
both. Each rule is proven red by a fixture: a package under
`tests/Aw.Architecture.Tests/Fixtures/`, the guard fixtures under `TypedIds/GuardFixtures/`, or a unit case in
`RegistryTests` or `FixtureTests`.

## Hosts

Every host has a DI validation test that calls the host's own `Compose` method (the one `Program.cs` calls), passing a test environment (a lambda, e.g. pointing `AW_STATE_DIR` at a temp directory) and a `FakeTimeProvider`, builds the container with `ValidateOnBuild` and `ValidateScopes`, and then resolves every registered `IService<,>` inside a scope (decorators are factory registrations that `ValidateOnBuild` can't see into).
