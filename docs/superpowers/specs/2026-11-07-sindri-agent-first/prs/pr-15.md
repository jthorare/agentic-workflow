# PR 15: Toolkit SDK and `/new-toolkit`

## Summary
A toolkit is a C# project (default `$AW_SINDRI_HOME/toolkits/<name>/`, or the overlay) that references the SDK and declares
itself: `Toolkit.Named("contracts").Needs(Resources.Database("cache"), ...).Tool<Req,Res>("diff_contracts", Handle)`. Request
and response are records with source-generated JSON; the tool's input schema comes from the request type
(`System.Text.Json` schema export over the source-gen `JsonTypeInfo`, so it stays AOT-safe). The SDK's `ToolkitHost.Run(args)`
serves those tools as an MCP stdio server with the official C# SDK (`ModelContextProtocol.Core`, pinned 2.2.0) and reads its
resources from the env names PR 14 defines. The generator follows `/new-package` and `/new-slice`: it writes the project,
a test project and one sample tool, then runs `dotnet build -warnaserror` and the tests under the heavy-job lock and reverts
on failure. PR 16 builds and runs these.
Rollback: revert.

The thing the design misses: toolkits live **outside the repo**, so none of the repo's build rails apply to them
(`Directory.Build.props`, `.editorconfig`, `Directory.Packages.props`, analyzers, `nuget.config` pinned to nuget.org with
locked restore, `global.json` with `rollForward: disable`). The generated toolkit must carry its own copies, and it must
get the SDK from somewhere that is not nuget.org. This card chooses a local folder feed at `$AW_SINDRI_HOME/sdk/packages`,
filled by `install-cs.sh` with `dotnet pack` of the SDK (stamped with the build), referenced by a toolkit-local
`nuget.config`. The owner can overturn it for a repo project reference.

## Graph context
- Nothing existing calls the SDK; `ModelContextProtocol.Core` is already used by Aw.Sindri.Infrastructure (csproj line 15) as a
  client (T3McpApi.cs), so the version pin and lock already exist (Directory.Packages.props:104).
- PR 14 owns the env names and the folder layout; the SDK reads them, it does not create them.
- PR 16 consumes `toolkit.json` (`--manifest`) to learn tools and needs before it starts a process.
- Generators' fan-out: the checks in `lib/checks.mjs` run `dotnet build -warnaserror` and tests under `scripts/heavy.sh`;
  only one generator runs at a time on the box (heavy-job rule in the owner's instructions).
- No `skills/` count change elsewhere: AGENTS.md says "58 native skills", update to 59.
