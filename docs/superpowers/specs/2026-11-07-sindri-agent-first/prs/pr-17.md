# PR 17: Workflows canvas and runs page

## Summary
The app gets back a Workflows page (PR 4 removed the old one). It lists workflows (active or off, last run, "changed by
session X" from the `By` on revision events), opens one as a **graph canvas** (layout computed by Sindri in PR 8, so the app
never lays out), shows the **runs** list and a run's detail (every node: status, input, output with the `truncated` flag,
error, usage, iterations of a `for_each`), live agent sessions with **Attach** and **Take over** (the existing
takeover and attach pieces), a Needs-you answer box for `ask_owner`, and Run now / Activate / Pause. Editing in the app
sends the same ops as `workflow_apply_ops` with a `baseRevision`, so a conflict with an agent shows a "reload" prompt.
The app holds no logic: it reads the HTTP API (it references no Sindri project) and gets live updates from the event stream.
Rollback: revert.

## Graph context
- The Home page and Work page already show items with run links (PR 4 and 6 `view_item_links`); both gain a "run" chip that opens
  the run in this page via `DeepLink` (Navigation/DeepLink.cs).
- Reads served by: PR 8's endpoints (`/sindri/workflows`, runs) and PR 6's `view_workflow_runs`; `workflow_get` returns layout.
- The Agents page (live sessions) is unchanged; Attach goes through the same launch-attach endpoints
  (`GetLaunchPicks`, `LaunchAttachView`).
- UI test rails: Aw.Sindri.Ui.Tests (view models), Ui.Controls.Tests, Ui.Frames.Tests (frame goldens), Ui.Rendering.Tests;
  the Avalonia headless runner and the aw-ui-driver (`UseAwUiDriver`) let an agent drive and screenshot the page.
- Nothing in Aw.Sindri.Core changes; if a field is missing from an API response, that is a PR 8 follow-up, not UI logic.
