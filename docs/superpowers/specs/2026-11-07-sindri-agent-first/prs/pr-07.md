# PR 7: `run_agent` on the existing launcher and agent runtime

## Summary
The launcher, launch ids, launch secret (SND-AUTH-003), `complete` report, `.sindri-out` recovery, idle watchdog,
takeover and handback are kept (PR 3 only cleared the recipe code around them). A node run now plays the role a Step run
played: `LaunchRequest.Run` (RunToken) and `LaunchRequest.Instance` (InstanceAddress) become a node-run address. The
block launches a session in a fresh worktree on `wf/<slug>/<run>`, inside the sandbox, with the repo's `github` host
group plus the host groups of the connections the node names, waits (Temporal wait, heartbeating), checks the report
against the node's declared `outputs`, closes the run (usage, diff signal, stop) and returns the declared fields plus
`status, branch, commit, sessionId, usage`. Proven on macOS (Seatbelt, owner's box) and Linux (bubblewrap) on a fixture repo pair.
Rollback: revert.

Naming trap in the design: run ids contain `:` and `@`. Session names (`snd-<launch id>`, `LaunchSessionName.cs:11`) and
git ref names cannot, so the launch id (`LCH-...`) stays the key everywhere and the branch is `wf/<slug>/<short-run>`.

## Graph context
- `LaunchId` (193 files), `LaunchRequest` (built by AgentLaunching only; read by Launcher, LaunchRecorder, AttendedOpen).
  Attended launches (`sindri open`) keep a null run; they do not change.
- `.sindri-out`: written by the agent through `StepFactWriter`/`complete`, read by `AgentRecovery`; both stay.
- Usage and diff signals: `UsageFlush`, `IRunDiff` (Infrastructure/Workflow/GitRunDiff.cs, kept in PR 3).
- Sandbox: `SandboxPlanner.cs:7` consumes `GroupsInput`; adding groups is data, not a planner change.
- Watchdog sweeps (`SweepLostSessions`) read launches and instances; after this PR they read launches and node runs.
- If macOS cannot host `run_agent` yet (SB-10, the first unattended run, is the open sandbox item in
  docs/csharp/sindri-sandbox.md), closing that is part of this PR's done check.
