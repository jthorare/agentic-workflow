# PR 1: Drop profile approval, edits apply on save

## Summary
Every profile write (`profile set`, `repo add`, `context pin set`, the app's forms) already validates and writes the live
`profile.yaml` atomically and then says "now approve it". After this PR the write is the whole story: runtime reads the
live file, `profile approve` answers "removed: edits apply on save", `--if-hash` stays as optimistic concurrency only.
Safe alone because validation (SND-PROFILE-*) is untouched and nothing else changes who may call what (that is PR 2).
Rollback: revert; the old approved snapshot is left on disk and is read again after a revert.

Cheapest route (the design under-counts this): `IApprovedProfile` is injected into 117 files under `src/`. Keep the
interface for one release and make `Latest()` return the live profile; delete `IApprovals`/`FileApprovals` and rename the
117 injection sites in a follow-up commit inside this PR, not by hand-editing each service first.
