# PR 5: Graph spec, revisions, validator, interpolation and conditions

## Summary
All the pure, testable parts of "a workflow is a JSON document": the spec types, the block-type registry contract
(config schema, declared outputs, example), the validator (one trigger, no cycle, upstream-only references, type-checked
references, cron and timezone, repo and connection names), `{{node.field}}` interpolation with type-keeping, the
`condition.when` language, and revisioned storage. No engine, no block runs. Safe alone: nothing calls it except
`sindri wf validate <file>` (in process, like `recipe validate` was), and drafts may save with wiring gaps.
Rollback: revert; no behavior depends on it yet.

  canvas layout (PR 17, which reads the same spec).
- Reuses: `ProfileRules` repo names for the repo check (Core/Profile/RepoState.cs, RepoEntry.cs), `Aw.Kernel` `Result`/`ErrorDefinition`,
  Vogen defaults (Core/VogenDefaults.cs), `MigrationRunner` (Aw.Kernel.Data/MigrationRunner.cs:26, backs up before upgrading).

  the old recipe tables, not in views.db.
