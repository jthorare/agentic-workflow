# PR 10: Connections

## Summary
A connection is a name (`linear:work`) that workflows, agents and toolkits use instead of a token. Rows hold only
non-secret config and a secret **pointer**; the secret is in the OS keychain (service `sindri-connection`, account
`<name>`) or an owner-only file under `$AW_SINDRI_HOME/secrets/` where there is no keychain, reusing the existing
`SecretPointer` schemes (env, file, keychain, op). `connection add` opens the browser to the provider's consent page
with PKCE and a `127.0.0.1:<port>` redirect; a built-in service refreshes tokens before expiry; a failed refresh
marks the connection `needs-sign-in`, adds a Needs-you row and fails the nodes that use it with that reason.
Presets (GitHub, Linear, Slack, Google, Spotify) ship without client ids (`--client-id` or the overlay supplies them).
Tests use a fake OAuth server; the real sign-in per provider is the owner's manual check at the end of this PR.
Rollback: revert.

## Graph context
- Existing `sindri index connect github|slack|linear` (Host/IndexSources/*Connect.cs) stores read-only index tokens in keychain
  service `sindri-index`. They stay separate in this PR (different scope and sign-off rules, docs/sindri/sources.md);
  a later change can let the index use a connection.
- Readers of connection data: GraphValidator (names), `run_agent` launch env (PR 7), `http` block (PR 9, adds `connection`),
  poll triggers (PR 11), toolkits (PR 16), memory blocks (none).
- Sindri's Features project is at the 4 project-reference limit (deps.yaml, Connectors edge note), so any adapter that needs
  another project goes in Host; this PR needs none (BCL `HttpListener`/`HttpClient` and existing packages).
- Secrets rule: nothing in the ledger, logs, MCP results or test output; `Aw.Redaction` covers `ConnectionSecrets` and the OAuth client's error text.
- Untrusted text: anything a provider returns into a prompt is marked untrusted like `/sindri/mcp` results (McpFencing.cs:13).
