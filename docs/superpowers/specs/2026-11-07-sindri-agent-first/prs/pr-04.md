# PR 4: Remove recipe and pipeline pages; item reads come from links

## Summary
PR 3 removed the backend and left the app and the reads compiling on history types. This PR removes what a person sees of
it and re-points the pages that stay. Item state stops being derived from recipe instances. An item keeps a plain
lifecycle plus **links** (Linear issue, PRs, graph runs); until PR 6 lands, an item with no link reads as plain
open/closed. The projector folds every retired event kind (`workflow.*`, `line.*`, `recipe.*`, `scope.*`, `profile.approved`)
as a timeline entry only, so old ledgers replay. Safe alone: no new feature, the app has one fewer page group.
Rollback: revert, then `sindri views rebuild`.
