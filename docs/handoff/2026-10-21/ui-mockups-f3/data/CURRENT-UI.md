## What tests pin (a redesign must keep these green or change the pinning test in the same PR)
1. **Tokens**: `TokenTests` pins every hex above, the exact set of colour keys (adding or removing a `Color.*` fails "every colour is one of the spec tokens"; `Brush.*` set must equal `Color.*` set), the ramp sizes/line heights, spacing/radius/size values. `ThemeResourcesTests`, `MotionTests`. New keys only via a phase contract unit.
2. **Contrast**: `ContrastTests` recomputes WCAG ratios per pair (Ink/Canvas 19.6, InkSubtle/Canvas 6.4, PrimaryHover/Surface1 6.6, OnPrimary/Primary 4.70, chips, Hairline 1.3 as decoration only). A light theme or a new surface colour needs new pairs; `Primary` as text fails by design (4.44:1).
3. **Fluent overrides**: `FluentOverrideTests` holds every Fluent value equal to its token; focus ring geometry in `FocusRingTests` (rendering project) requires >=4 px around each focusable control.
4. **No hex outside Theme/**, and InkTertiary only for disabled text (unit lane scans sources).
5. **Action catalog**: `ActionLabelsTests` loads `tests/Aw.Sindri.Tests/Golden/Api/commands/catalog.json` (54 action ids, classes desk/protected/pause/job/issue/decision/request/local) and requires every id to have a unique label in `Labels.Actions.cs` with no ':' in it. A mockup may rename a label (edit `Labels._actions`) but every id keeps exactly one unique label; new ids need a golden + label. Protected class actions must render as a copy-CLI block (`ProtectedActionButton`), the UI can't send them; Review verbs sent by the app are pinned to the desk subset.
6. **API goldens**: `Golden/Api/**` (Sindri-owned, wire contract) and `Golden/SpecShaped/**` (queue, status, items, needs-you, services, workflow-instance-fact...) drive `FakeSindriApi`; a mockup that needs a field no route serves (agents, recipe stats, engine, per-edge health) is a **not served yet** panel, never fake data.
7. **View frames/behaviour tests** (headless): `*FramesTests` (Catalog, Needs-you, Queue, Instance, Children, Facts, Recipe, Workflows, WorkflowsStrip), `StripFoldTests` (home fold at 1280x800), `ResponsivePageTests`, `BannerLayoutTests` (900 px), `NamedControlsTests` (every `x:Name` field non-null), `AutomationPeerTests`, focus tests (`*FocusTests`, `RegionKeysTests`, `ChordKeysTests`), `RealFontTextFitTests`. Layout moves (row heights, columns, nav structure) will break fold/fit/focus-order assertions; names of `x:Name` controls are test hooks.
8. **Nav**: `ShellNavTests`, `ShellChordTests`, `TopBarTests`, `NavTabClickTests`: the 7 pages + chords are asserted; a sidebar replacing the top bar means rewriting these, plus `TopBar.Counts` step-down at 900 px.
9. **Copy**: `LabelsTests`, `SpecTextTests` (assert specific spec sentences exist in the spec file), `docs` tests; the spec file must be edited with any wording change.
10. `deps.yaml`/`check-deps`: SindriUi has no Sindri project reference, only http + file edges; the UI holds no logic (views bind VM text via `ShellText`).

## Breaks goldens vs safe
- Safe: palette-only change of Tokens hex (update TokenTests/Contrast/Fluent in the same change), fonts, radius, spacing, restyling `.axaml` styles, new purely-visual components, new VMs behind existing data.
- Breaks tests: renaming/removing/adding a `Color.*` key; changing a Fluent override without its token; changing any `x:Name`; changing the 900x600 min / fold math; adding a shadow is not pinned but violates the stated "no shadows" spec line (spec edit needed); light theme (Dark-only assumption in token tests, FluentOverrides palette key `Dark`).
- Breaks API goldens: any new field the client must read (add to golden + `SindriUiJsonContext`), any new route (needs `deps.yaml` http edge and `/sindri/` literal found by check-deps).

## Context screen: what it is meant to show (for the mockup builder)
Purpose: one **anchor** (a node key such as `feature:tabs.tab-manager`, or a set of up to 20; a file, record or node) seen through three stores at once. Rev 8 prototype (`mockups/context.png`) is the target; the current app has only the page head and an empty `LensStackHost`.

**Header row**: title "Context", map status line `map v13 current · draft v14 (46 proposals) · code index 03:00 failed · intent 2h behind` (failed marked with ✕ glyph), right side `[Build draft]` (BuildContextMap/ProposeContextMap, job) and `[⌂ Promote · terminal]` (PromoteContextMap, protected: copy CLI, note "keeps the 46 pending proposals").
**Control row**: anchor box (`⌘/`, placeholder "node · file · record", accepts key, path or record id; ambiguous input returns suggestions SND-CONTEXT-003 / candidates -037), `depth 2 ▾` (neighbour depth), lens toggles `☑ intent ☑ product ☑ files ☐ symbols (index not built) ☐ draft`, and a `graph | tree` switch (tree = file-map view).
**Lens stack** = three horizontal bands stacked on one vertical axis (the central visual; this is where a graph canvas goes):
1. **INTENT band** (top): header "Intent · Linear · Slack · Onyx", right meta "5 records · 2 decisions · 1 conflict". Content: record chips (mono: `ENG-482 "Restore panes per window"`, `PRD-tabs.md §3 (linear:doc)`, `#tabs-design 09-30 (slack)`, orphaned `ENG-301 ⚠ orphaned` dashed border), and a **decision card** (`◇ decision "…"`, `supersedes ◇ "…" 09-12`, a `⚠ conflict with PRD §3.2 ▸` pill that opens both quotes side by side).
2. **PRODUCT GRAPH band** (middle, slightly lighter surface): header "Product graph · features · surfaces · actions · things · flows", right meta "own scope 7 · affects 3 at depth ≤ 2". A real node-edge graph: nodes are mono rounded rectangles named `kind:key` (feature, surface, action, thing, flow), edges labelled with type (`part-of`, `reads`, `writes`, `on`, `step-of`), neighbours tagged `d1`, `d2 (dep)`. The **anchor** node has a lavender-ring outline + ▣ glyph + "◀ anchor" tag; ⚠ marks a conflict on a node.
3. **CODE band** (bottom): header "Code · files · symbols", right meta "map v13 · 6 files · index not built · 1 feature with no code". File chips (`src/layout/SplitPane.ts #setOrientation #split`), test file chips, a model-suggested link chip (`◇ suggested, unconfirmed`, dashed), and a `calls A → B → C` line from the symbol index.
**Cross-band edges** drawn as vertical lines between bands, labelled: intent→product `decides` / `mentions`; code→product `implements` / `tests` (`implements (model-suggested 0.74)` dashed). Edge fields served: `from, to, type, provenance, link, confirmed, confidence`. Provenance and trust (trusted/untrusted) must read: confirmed = solid, model-suggested = dashed + ◇ + confidence.
A lens toggled off collapses its band to a single header line. Truncation flags per band (`truncated`) mean "N more" affordance. Degraded/searched metadata tells which source answered (states ok, degraded, unavailable, not-configured).
**Coverage strip** (surface block under the stack): "Coverage of the anchor's scope (7 nodes)" with three segmented bars: `intent 5/7 cited`, `product 7/7 confirmed`, `code 6/7 implemented`; a `gaps` line naming nodes (`surface:dialog/restore-layout has a PRD mention but no code`, `feature:session.restore code only, no intent`) and `[Open gaps]` (filters the review queue to them).
