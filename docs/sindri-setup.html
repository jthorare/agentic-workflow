    Sindri · C# build

    Set up Sindri

    Eight steps take a new Mac to this picture: Sindri running, Onyx connected, agents able to reach it, and the app open.

    HUMAN-ONLY type it in your own terminal, not in an agent session. AGENT OK an agent may run it for you.

    Always type sindri-app

    Until the C# build replaces it, sindri on your PATH is the TypeScript Sindri, with its own profile. Sindri's hints say sindri …: read every one as sindri-app …. A copied sindri profile approve <hash> answers SND-PROFILE-006 … does not match the current profile.

    Why some commands are human-only (SND-AUTH-002)

    Approving the profile, starting Sindri, onyx up, MCP registration and every later approval are a person's decisions: an agent that could run them could widen its own config and approve its own work.

    The CLI acts for a person only at a real terminal with no agent among its parent processes. Otherwise Sindri refuses with SND-AUTH-002 and names what it saw. Run those commands yourself; don't try to get around the check.

    Step 1

    Prepare the Mac

    Install Docker yourself (Onyx needs about 5.5 GiB of Docker memory and 10.5 GiB of disk). The script fetches the rest.

    HUMAN-ONLYuv, graphify, the pinned Temporal binaries and any missing system packages (AW_DRY_RUN=1 prints only, agent OK)
    scripts/install-deps.sh

    Your own terminal, not an agent session.

    You should see

    === External tools (uv, graphify, Temporal, system packages) ===
  uv: already installed (uv 0.12.24 …)
  graphify: already installed (0.9.67)
    What each piece is for
    • .NET SDK 10.0.401 (global.json) builds Sindri; step 2 installs it into ~/.dotnet when missing.
    • Temporal CLI runs workflow instances; pinned in binaries.lock.
    • Docker with Compose 2.24 or later runs Onyx.
    • graphify in a sandbox (sandbox-exec on macOS, bwrap on Linux) groups the product map.
    If it didn't work
    • A system package is missing: the script installs it with Homebrew (or apt, dnf…); AW_NO_SYSTEM_INSTALL=1 prints the commands instead.
    • Docker memory too small: Docker Desktop → Settings → Resources.

    Step 2

    Build and link sindri-app

    One script builds the C# Sindri for this Mac and puts sindri-app on your PATH.

    HUMAN-ONLYFrom the agentic-workflow checkout (a heavy build)
    scripts/sindri-app.sh status

    Your own terminal, not an agent session.

    You should see

    sindri-app: linked ~/.local/bin/sindri-app -> …/scripts/sindri-app.sh
sindri-app: built ~/.agentic-workflow/bin/sindri-app/1538a9f30cfc7caf
SND-API-001 not running: … (expected: step 4 starts it)
    Why sindri-app, and how builds work
    • sindri stays the TypeScript Sindri until the switch, so the C# build has its own name.
    • A build is stamped with a hash of its source: a source change rebuilds, nothing else does. --rebuild forces it.
    • One build at a time (a lock), in the box-wide heavy-job slot; the current and the previous builds are kept.
    • It builds from the checkout its link points at: git pull there first, or you get an older build.
    If it didn't work
    • publishing sindri failed: the log's tail is printed; the full log is ~/.agentic-workflow/cache/sindri-app-build/publish.log.
    • … is not on your PATH: add ~/.local/bin to PATH.
    • waiting for another sindri-app publish: another build runs; this one continues when it ends.

    Step 3

    Write and approve the profile

    The profile names your repos and what Sindri may read. Sindri runs only the version you approved.

    FILE~/.agentic-workflow/sindri-app/profile/profile.yaml
    schemaVersion: 1
user: you
repos:
  - name: my-app
    path: /Users/you/code/my-app
    index: { denyPaths: ["db/migrations/**/*.json", "**/*.png"] }
services:
  context-docs-refresh: { every: 5m }
context:
  repos: [my-app]
  docs: { globs: ["AGENTS.md", "README.md", "docs/**/*.md"] }
  sessions: { enabled: true }
    HUMAN-ONLYShows the hash; run it again with the hash and type approve profile <6 digits>
    sindri-app profile approve

    Your own terminal, not an agent session.

    You should see (sindri-app profile validate)

    Profile valid: ~/.agentic-workflow/sindri-app/profile/profile.yaml
hash 73ce9910…470b, approved
    What the keys do
    • denyPaths: files Sindri never reads for the map, on top of the built-in secret globs.
    • context-docs-refresh: indexes the repo's docs every 5 minutes; nothing is indexed without it.
    • sessions.enabled: lets agent sessions read context over MCP.
    • Step 5 adds the Onyx section for you. Every change needs another approval; until then Sindri keeps the last approved one.
    If it didn't work
    • SND-PROFILE-002: a typo or unknown key; the message names the key path.
    • SND-PROFILE-003: the file changed since you copied the hash; run the preview again.
    • SND-PROFILE-006 … does not match the current profile: you typed sindri, the TypeScript CLI. Use sindri-app. (From sindri-app, 006 means the approved snapshots can't be read or written: check permissions and disk.)

    Step 4

    Start Sindri

    Start it once; it keeps running when you close the terminal. doctor checks every part.

    HUMAN-ONLYStarts it in the background (plain sindri-app also opens the app)
    sindri-app --headless

    Your own terminal, not an agent session.

    You should see (sindri-app doctor, agent OK)

    ok    lease             held by my-mac/53290 since …, epoch 6
ok    ledger            schema 6/6
ok    profile           approved, hash 73ce99
ok    api               127.0.0.1:7410 answers (pid 53290, epoch 6)
ok    temporal          127.0.0.1:53876 answers (pid 53346), version 1.9.1 as pinned, namespace sindri present
    Reading doctor
    • Each line is ok, warn or fail, with its fix. The context:* and onyx:stack lines turn ok in step 5.
    • Agent-probe lines (claude-code, codex:*, cursor-*) that say "differs" or "pending" are normal on a dev box.
    • After a new build the running Sindri keeps its old one: sindri-app stop, then start again.
    • The first start without Onyx offers to set it up: say no here and do step 5.
    If it didn't work
    • SND-API-001 … ask the human to run 'sindri': an agent can't start Sindri. Run it yourself.
    • SND-LEASE-001: Sindri already runs on this Mac; use that one.
    • SND-CLI-002: it or Temporal didn't come up; read ~/.agentic-workflow/sindri-app/logs/serve.log and temporal.log.
    • SND-API-003: port 7410 is taken; set api: { port: … } in the profile.

    Step 5

    Add Onyx, then connect Linear and Slack

    One command runs a pinned Onyx in Docker on 127.0.0.1 and gives Sindri its own Onyx user. Then connect your sources in Onyx's web page.

    check the Mac→pinned files→pull images→start→you: sign up→you: your admin login→Sindri's user + key→you: approve profile
    HUMAN-ONLYSafe to rerun: it resumes where it stopped
    sindri-app onyx up

    Your own terminal, not an agent session.

    You should see (sindri-app doctor)

    ok    context:onyx      Onyx v4.9.0 answers on 127.0.0.1:3000 (pinned v4.9.0); key: admin, Sindri's dedicated user
ok    context:sources   2 of 2 sources ok; session reads on
ok    onyx:stack        9 containers running, healthy, bound to 127.0.0.1:3000, digests match the pins
    Connect Linear and Slack
    • onyx up ends on Onyx's connectors page. Add Linear (the product's teams, with a start date far enough back) and Slack (the product's channels).
    • These use your company's OAuth: get sign-off first. Sindri never connects a source itself.
    • Onyx indexes in the background; a large workspace takes a while.
    Your login and Sindri's user
    • It asks once for your own Onyx admin login (the account you just signed up with). The password isn't shown or stored.
    • With it, Sindri makes its own user, sindri@example.com, and a token kept in the macOS keychain. You never type that address.
    • Onyx's data survives sindri-app stop and onyx down.
    If it didn't work
    • SND-ONYX-001: Docker isn't running. SND-ONYX-003: not enough memory or disk (the message says how much).
    • SND-ONYX-007: that login isn't an Onyx admin; use your first account.
    • SND-ONYX-008: invite-only Onyx; invite sindri@example.com once in Admin → Users, then rerun.
    • warn context:onyx SND-CONTEXT-053: the key came from an older build; update, rebuild, restart, rerun onyx up.

    Step 6

    Let Sindri launch agents

    A launcher file tells Sindri how this Mac opens a terminal; the profile names the agent it starts there.

    HUMAN-ONLYFinds your terminal and writes ~/.agentic-workflow/launcher.json (your call: Sindri doesn't refuse an agent here)
    sindri-app launch init

    Your own terminal, not an agent session.

    PROFILEAdd to the profile, then approve it again (step 3)
    workflow:
  agent: { target: claude-code }

    You should see (sindri-app launch show, agent OK)

    Terminal: warp (file) · ~/.agentic-workflow/launcher.json
claude-code  builtin  /opt/homebrew/bin/claude  sha256:658e…3acd  Steps: ok
codex        builtin  ~/.local/bin/codex        sha256:3a5a…7c7f  Steps: ok
cursor       builtin  ~/.local/bin/agent        sha256:1e0a…9495  Steps: ok
    Why
    • Without both, a workflow Step that needs an agent waits on your desk instead.
    • launch init --stdout previews the file; an existing file needs --force.
    • target is claude-code, codex, cursor, or an agent you added to launcher.json.
    If it didn't work
    • SND-LAUNCH-002: no terminal it can open (no Warp, no desktop session); pick one with --viewer.
    • SND-LAUNCH-003: the agent CLI isn't on your login PATH.
    • SND-LAUNCH-011: launcher.json isn't valid; the message names the key.

    Step 7

    Connect agent sessions over MCP

    Register Sindri in your work repo, so agent sessions there can ask it for context.

    HUMAN-ONLYIn the work repo: Claude Code, Cursor and Codex, for this repo only
    cd ~/code/my-app
sindri-app mcp register --apply --providers all

    Your own terminal, not an agent session.

    You should see (sindri-app doctor)

    ok    context:sources   2 of 2 sources ok; session reads on
ok    context:mcp-scope no user-wide 'sindri' MCP entry for Claude Code, Codex or Cursor
    Why per repo
    • Registration is never user-wide, so work context never shows up in personal repos.
    • Starting Sindri with plain sindri-app from the repo prints this command; it can't run it for you, so run it once, and again when the port changes.
    • sindri-app mcp register without --apply previews it (agent OK).
    If it didn't work
    • SND-CONTEXT-024: this folder isn't a profile repo; cd into it or pass --repo my-app.
    • failed on .cursor/mcp.json or .codex/config.toml: git tracks it; add the printed entry by hand.
    • Sessions get SND-CONTEXT-020: set context.sessions.enabled: true and approve.

    Step 8

    Open the app

    The app is a window onto Sindri: what needs you, its health, and your workflows.

    HUMAN-ONLYFinds the running Sindri and opens the app
    sindri-app

    Your own terminal, not an agent session.

    You should see

      profile   ~/.agentic-workflow/sindri-app/profile/profile.yaml (approved, hash 73ce99)
  health    healthy
  api       127.0.0.1:7410
  ui        opened (sindri-ui, pid 61022)
  ready     running

    ✓ You're set up. Closing the app doesn't stop Sindri.

    What next

    Building the product map, approving recipes and running workflows move into the app. Until they land there, they're in OPERATIONS.md.

    If it didn't work
    • ui not found at …: sindri-ui sits beside sindri in the build; rebuild with scripts/sindri-app.sh --rebuild, or set AW_SINDRI_UI.
    • The app can't reach Sindri: sindri-app status, and start it again if it stopped.
