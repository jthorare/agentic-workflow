# GraphWorkflow

- **Models:** `GraphRunStarter.Start` and `Launch` (the in-flight read, the skip, the insert as Running or Queued, a failed launch marking the run Failed), `SqliteWorkflowRunStore.Admit` (the used-id check, the in-flight read and the insert in one `BEGIN IMMEDIATE` transaction; a used id is SND-GRAPH-100), `InFlight` (queued, running and waiting rows of the workflow) and `SetStatus`. The end-of-run path is `GraphRunActivities` (the run's end calls `GraphRunStarter.StartNextQueued`, which starts the oldest Queued run through the one-transaction `SqliteWorkflowRunStore.PromoteOldestQueued`); a failed launch in `Start` calls it too. Cancel of a Queued run is modelled; cancel of a running run is the workflow's own end (`End` with `cancelled`).
- **Bounds:** 4 triggers over 2 workflows (3 on `w1`, 1 on `w2`), at most one re-delivered trigger, each workflow in one mode. `GraphWorkflow.cfg`: `w1` queue with a re-delivery, `w2` one-per-workflow. `OnePerWorkflow.cfg`: `w1` one-per-workflow, `w2` queue. `Unlimited.cfg`: `w1` unlimited with a re-delivery. Weak fairness on the starter steps, launch, resume and end.
- **Checks:** `NoDuplicateRunIds`, `AtMostOneInFlight` (running or waiting, one-per-workflow and queue), `QueuedStartFIFO` (no run starts while an older one is Queued) and `QueuedLeavesQueued` (a Queued run is eventually started or cancelled).
- **Gaps** (`gaps/`, run with `--witnesses`, each must fail on the invariant its line 1 names): `CheckThenInsert` (read and insert in two transactions), `StrandedByStaleRead` (a Queued insert after the last run ended), `NewestQueuedFirst`, `FailedLaunchStrandsQueue`, `BlindInsert`, and three `Reach*` cases that prove the drain, the skip and the refusal are reachable.
- **Atomic start:** the passing configs set `StartAtomic = TRUE` (the in-flight check and the insert are one step). That is the code: `GraphRunStarter.Start` makes one `IWorkflowRunStore.Admit` call, which checks the id, reads the runs in flight and inserts in one transaction. `gaps/CheckThenInsert.cfg` and `gaps/StrandedByStaleRead.cfg` plant the old two-transaction shape (read, then insert).
- **Required of the end path:** `LaunchFailDrains = TRUE`. A failed launch marks the run Failed and must also start the oldest Queued run, or a queued run behind it is stranded (`gaps/FailedLaunchStrandsQueue.cfg`). The code does: `GraphRunStarter.Start` calls `StartNextQueued` after a failed launch (test `GraphRunStarterTests.A_failed_launch_starts_the_next_queued_run`).
- **Test runs (P4a, spec 2026-11-12 §3.2):** `TestTrig` names the one trigger that asks for a test run (`mode = test`); `TestCounts = FALSE` is the code (the admit path filters `mode = live`, so a test takes no slot and queues behind nothing, and a live trigger counts live rows only), `TestFenced = TRUE` is the code (a test run's write ports record). Checks: `TestRunWritesNothing` and `LiveNeverWaitsOnTest` (in `GraphWorkflow.cfg` and `OnePerWorkflow.cfg`). Gaps: `TestWrites` (unfenced ports) and `TestBlocksLive` (Admit counts test rows).
- **Run time:** under a minute for the folder with `--witnesses`. Liveness (`QueuedLeavesQueued`) is checked in `GraphWorkflow.cfg` only; `OnePerWorkflow.cfg` and `Unlimited.cfg` check safety only.
